# FraudGuard AI – Machine Learning Pipeline

This directory contains the end-to-end machine learning pipeline for **FraudGuard AI**, including data ingestion, stratified preprocessing, cost-sensitive model training, performance evaluation, and SHAP-based local and global explainability.

---

## 📋 Execution Order

Execute the pipeline scripts in the following sequence from the repository root:

```bash
# 1. Preprocess data and build transformer artifacts
python ml/src/preprocess.py

# 2. Train models with stratified cross-validation and select the best model
python ml/src/train.py

# 3. Evaluate the champion model on the held-out test set
python ml/src/evaluate.py

# 4. Generate SHAP explainers and global feature attribution summary
python ml/src/explain.py
```

---

## 🛠️ Pipeline Details

### Step 1: Preprocessing & Feature Engineering
- **Script**: `ml/src/preprocess.py`
- **What it does**:
  1. Loads raw PaySim transaction data from `ml/data/raw/`.
  2. Standardizes column names to `snake_case`.
  3. Engineers `hour_of_day = step % 24` representing cyclical transaction timing.
  4. Drops identifiers (`nameOrig`, `nameDest`, `step`, `isFlaggedFraud`) to prevent label leakage.
  5. Performs a **stratified 80/20 train/test split before fitting** or resampling to ensure zero data leakage.
  6. Fits a scikit-learn `ColumnTransformer` with `StandardScaler` for numeric features and `OneHotEncoder(handle_unknown="ignore")` for transaction types.
- **Outputs**:
  - `ml/models/preprocessor.joblib`: Serialized ColumnTransformer used by both offline evaluation and backend API inference.
  - `ml/models/feature_names.json`: Ordered list of one-hot encoded and scaled feature column names.

---

### Step 2: Model Training & Selection
- **Script**: `ml/src/train.py`
- **What it does**:
  1. Compares three competitive classification algorithms:
     - **Logistic Regression**: `class_weight="balanced"`, `max_iter=1000`.
     - **Random Forest**: `n_estimators=200`, `class_weight="balanced_subsample"`.
     - **XGBoost**: `scale_pos_weight = n_legit / n_fraud`, `eval_metric="aucpr"`.
  2. Evaluates each candidate using **Stratified 3-Fold Cross-Validation** scored on **PR-AUC (Average Precision)**, the gold standard for severe class imbalance.
  3. Relies on class weights rather than synthetic oversampling (SMOTE) to preserve calibration and prevent synthetic artifact distortion in tree splits.
  4. Automatically selects the champion model by highest PR-AUC and serializes it.
- **Outputs**:
  - `ml/models/fraud_model.joblib`: Champion model artifact (`XGBClassifier`) deployed to the backend.
  - `ml/models/model_comparison.json`: Side-by-side performance metrics across all evaluated architectures.

---

### Step 3: Model Evaluation
- **Script**: `ml/src/evaluate.py`
- **What it does**:
  1. Evaluates the saved model on the held-out test set.
  2. Computes Precision, Recall, F1-Score, PR-AUC, and ROC-AUC at the default decision threshold (`0.5`).
  3. Performs sensitivity threshold sweep from `0.1` to `0.9` to guide operational operating points.
  4. Generates diagnostic evaluation visualizations.
- **Outputs**:
  - `ml/reports/metrics.json`: Machine-readable evaluation metrics read by the backend `/api/model/metrics` endpoint.
  - `ml/reports/confusion_matrix.png`: Annotated test set confusion matrix.
  - `ml/reports/precision_recall_curve.png`: PR curve annotated with PR-AUC score.
  - `ml/reports/roc_curve.png`: Receiver Operating Characteristic curve.
  - `ml/reports/feature_importance.png`: Top 10 feature importance bar chart.
  - `ml/reports/threshold_analysis.csv`: Precision, recall, and F1 trade-offs across thresholds 0.1–0.9.

---

### Step 4: Model Explainability (SHAP)
- **Script**: `ml/src/explain.py`
- **What it does**:
  1. Initializes `shap.TreeExplainer` on the champion model.
  2. Implements local single-transaction explanation (`explain_transaction`) which:
     - Merges one-hot `transaction_type_*` categories into a unified `"transaction_type"` attribution.
     - Maps sign to direction labels (`increases_risk` vs `decreases_risk`).
     - Normalizes SHAP output shapes across multi-class list and 2D log-odds arrays.
  3. Computes global SHAP summary attributions on a 2,000-row test sample.
- **Outputs**:
  - `ml/reports/shap_summary.png`: Beeswarm summary plot showing the direction and magnitude of feature impacts across transactions.
